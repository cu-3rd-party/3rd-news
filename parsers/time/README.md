# Парсер TiMe

Читает каналы мессенджера ЦУ (`time.cu.ru`) и шлёт объявления в 3rd-news.

TiMe — это Mattermost, так что парсер ходит в его `/api/v4`. Адрес канала из
браузера разбирается как есть: из
`https://time.cu.ru/tsentralnyy-universitet/channels/anonsy-tsu` получаются
команда `tsentralnyy-universitet` и канал `anonsy-tsu`, а slug источника в
3rd-news становится `time-tsentralnyy-universitet-anonsy-tsu`.

## Авторизация

Токен сессии лежит в HttpOnly-куке `MMAUTHTOKEN`. Из JS его не достать —
только из браузера целиком. Готовый способ уже есть в соседнем репозитории:
[`tools/chrome-cookie-exporter`](https://github.com/cu-3rd-party/3rd-view/tree/main/tools/chrome-cookie-exporter)
из `3rd-view` копирует строки `TIME_COOKIE` и `TIME_CSRF` в буфер.

Руками — то же самое: DevTools → Network → любой запрос к `time.cu.ru` →
Copy → Copy as cURL, оттуда взять значение заголовка `cookie`.

```bash
TIME_COOKIE='MMAUTHTOKEN=...; MMUSERID=...; MMCSRF=...'
```

Куки живут не вечно. Когда протухнут, парсер напишет в лог
`TiMe отвечает 401 ... Скорее всего протухли куки` и остановится — молча
крутиться вхолостую он не будет.

Если админы TiMe разрешают personal access token, лучше взять его:
`TIME_TOKEN=...` вместо кук, он не протухает.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `NEWS_URL` | `http://main:8000` | адрес 3rd-news |
| `NEWS_API_KEY` | — | ключ с правом `ingest`, выпускается в админке |
| `TIME_COOKIE` | — | строка кук из браузера |
| `TIME_CSRF` | — | значение `MMCSRF`, необязательно (мы только читаем) |
| `TIME_TOKEN` | — | personal access token вместо кук |
| `TIME_CHANNELS` | — | первичный выбор каналов, если он ещё пуст |
| `PARSER_API_TOKEN` | — | если задан, ручки требуют `Authorization: Bearer` |
| `STATE_PATH` | `/data/state.json` | где лежит выбор каналов |
| `CHANNEL_CACHE_TTL_S` | `300` | кэш списка каналов (его сбор — девять запросов) |
| `TIME_BASE_URL` | `https://time.cu.ru` | |
| `POLL_INTERVAL_S` | `600` | пауза между проходами |
| `MAX_AGE_DAYS` | `30` | посты старше игнорируются |
| `TIME_MAX_PAGES` | `5` | сколько страниц по 60 постов читать за проход |
| `TIME_INCLUDE_REPLIES` | `false` | тащить ли ответы в тредах |
| `TIME_AUTHORS` | `privileged` | `privileged` — только авторы с правами в канале; `all` — все подряд |
| `TIME_DOWNLOAD_ATTACHMENTS` | `true` | скачивать ли вложения |
| `TIME_MAX_ATTACHMENT_BYTES` | `67108864` | лимит на файл |

## Где выбирать каналы

`http://localhost:8201` — страница выбора. Поиск, фильтры, сортировка по
активности, галочки. Справа видно, что парсится сейчас и чем кончился
последний проход по каждому каналу.

Страница живёт в самом парсере, а не в общей админке 3rd-news: та про TiMe,
команды и каналы ничего не знает, и знать не должна — иначе каждый новый
парсер начал бы тащить свои понятия в общий интерфейс.

При первом заходе она спросит `PARSER_API_TOKEN` и запомнит его в
localStorage. Сама страница и Swagger отдаются без токена — данных в них нет,
все запросы к API он всё равно требует.

## Ручки выбора каналов

Каналов в ЦУ больше полутора тысяч, поэтому парсер поднимает собственный
маленький API — посмотреть, поискать, выбрать. Ручки в главном сервисе для
этого не заводились: про TiMe и его каналы знает только парсер, ядро от этих
понятий свободно.

Все ручки, кроме `/health`, требуют `Authorization: Bearer $PARSER_API_TOKEN`,
если токен задан. Список каналов рабочего мессенджера — не для всех.

| Ручка | Что делает |
| --- | --- |
| `GET /channels` | все каналы: поиск, фильтры, сортировка, постранично |
| `GET /channels/selected` | что сейчас парсится и как прошёл последний проход |
| `POST /channels/selected` | добавить (ссылкой из браузера или `команда/канал`) |
| `PUT /channels/selected` | заменить весь выбор целиком |
| `DELETE /channels/selected?channel=…` | убрать один |
| `POST /poll` | прогнать прямо сейчас |
| `GET /teams` | команды пользователя |
| `GET /status` | состояние: авторизован ли, сколько выбрано, итоги прогонов |

Параметры `GET /channels`: `q` (ищет по имени, названию и описанию),
`team`, `only_joined`, `only_selected`, `only_with_posts` (по умолчанию да),
`active_within_days`, `sort` (`activity` по умолчанию, ещё `messages` и
`name`), `limit`, `offset`, `refresh` (обойти пятиминутный кэш).

**Личных переписок в выдаче нет никогда.** У обычного аккаунта их шестьдесят
штук вперемешку с рабочими каналами; типы `D` и `G` отсекаются в клиенте, а
не у вызывающего, чтобы фильтр нельзя было случайно обойти.

Выбор хранится в `/data/state.json` (том `time_state`) и переживает
пересборку. `TIME_CHANNELS` заполняет его только при первом старте, пока
выбор пуст — иначе рестарт контейнера откатывал бы всё, что настроили руками.

### Как это выглядит на практике

```bash
TOKEN=...  # PARSER_API_TOKEN
B=http://localhost:8201

# найти нужный канал
curl -sG "$B/channels" -H "Authorization: Bearer $TOKEN" --data-urlencode "q=anons"

# добавить его ссылкой прямо из браузера
curl -X POST "$B/channels/selected" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"channels":["https://time.cu.ru/tsentralnyy-universitet/channels/anonsy-tsu"]}'

# разово затянуть историю поглубже, не меняя фоновый опрос
curl -X POST "$B/poll?max_age_days=365&max_pages=5" -H "Authorization: Bearer $TOKEN"
```

Для поиска по-русски обязателен `--data-urlencode`: `curl` в Git Bash
кириллицу в URL портит.

## Запуск

```bash
docker compose --profile parsers up -d parser-time
```

API поднимется на `http://localhost:8201`, Swagger — на `/docs`. Фоновый
опрос выбранных каналов идёт в том же процессе раз в `POLL_INTERVAL_S`.

Или локально:

```bash
cd parsers/time
NEWS_URL=http://localhost:8000 NEWS_API_KEY=tnk_... \
TIME_COOKIE='MMAUTHTOKEN=...' \
TIME_CHANNELS=https://time.cu.ru/tsentralnyy-universitet/channels/anonsy-tsu \
    python -m app.main
```

## Что и как превращается в новость

- **Ответы в тредах пропускаются.** В «Анонсах ЦУ» их больше половины, и это
  вопросы студентов под объявлением, а не объявления. Включить —
  `TIME_INCLUDE_REPLIES=true`.
- **Пишут новости только те, кому это доверено.** Пост берётся, если у его
  автора в канале есть права сверх обычного участника. Проверять на
  `channel_admin` было бы ошибкой: в «Анонсах ЦУ» этой роли нет ни у кого —
  там своя схема прав, и роли названы её идентификаторами. Значим не ярлык, а
  то, что права шире, чем у рядового участника (гостевая роль тоже не в счёт).

  В чате потока это отсекает вопросы студентов, не потратив ни одного токена
  на классификацию: из 18 корневых постов East-chat остаётся 6, и это ровно
  объявления кураторов. В новостных каналах не меняет ничего — там и так
  пишут только свои. Отключается через `TIME_AUTHORS=all`.
- **Системные и удалённые посты пропускаются.**
- **Пост из одной картинки без подписи сохраняется.** Афиша без текста — тоже
  анонс.
- **Заголовок берётся из первой строки**, если она на него похожа: снимается
  разметка и эмодзи, так что `**Стартуем в новый учебный год**
  :cu-black-hat:` даёт `Стартуем в новый учебный год`. Если текст в одну
  строку или первая строка длиннее 150 символов — заголовка не будет, тело
  от этого не страдает.
- **Тело — сырой Markdown поста**, как его написали. Ничего не вырезается.
- **Вложения скачиваются и уходят файлами.** `/api/v4/files/...` требует
  авторизации, по ссылке главный сервис ничего бы не получил. Файл, который
  не скачался, из новости убирается — лучше без вложения, чем со ссылкой в
  никуда.
- `external_id` — id поста, поэтому ленту можно перечитывать сколько угодно:
  повторы вернутся как `duplicate`.
- Ссылка на оригинал — пермалинк вида `{base}/{команда}/pl/{id}`.
- Автор и факт правки поста уходят в `extra`, на классификацию не влияют.

## Тесты

В корне репозитория: `tests/test_parser_time.py` (разбор постов) и
`tests/test_parser_time_channels.py` (перечисление каналов и хранилище
выбора — там же проверка, что личные переписки отсекаются).

Фикстура `tests/fixtures/time_posts.json` синтетическая: форма ответа снята
с живого канала, а тексты выдуманы — репозиторий публичный, настоящие
внутренние объявления в него не кладутся.
