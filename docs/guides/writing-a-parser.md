# Как написать парсер

Парсер — отдельная программа, которая читает какой-то канал вуза и шлёт новости
в главный сервис. Он не обязан жить в этом репозитории и не обязан быть на
Python: весь контракт — это один HTTP-запрос, см.
[`docs/contracts/ingest.md`](../contracts/ingest.md).

## 1. Получите ключ

В админке → **API-ключи** → создать с правом `ingest`. Если сразу привязать ключ
к источнику, поле `source_key` в запросах можно не заполнять.

Ключ показывается один раз — сервер хранит только его хэш.

## 2. Напишите цикл

Скопируйте [`parsers/template`](../../parsers/template) и заполните
`fetch_items()`:

```python
from thirdnews_contracts import IngestClient, NewsSubmission

client = IngestClient("https://news.example.edu", api_key=API_KEY)

client.submit(NewsSubmission(
    external_id="12345",              # стабильный id поста в источнике
    source_key="tg-dekanat-fkn",
    body_md="Текст в **markdown**",
    source_link="https://t.me/dekanat_fkn/12345",
    published_at=post_datetime,
))
```

**Состояние хранить не нужно.** Приём идемпотентен по `(source_key,
external_id)`, поэтому проще всего каждый раз перечитывать последние N постов и
слать всё подряд: повторы вернутся со `status: "duplicate"` и ничего не изменят.

## 3. Вложения

Если файл доступен по прямой ссылке — просто отдайте URL, сервис скачает его
сам, асинхронно:

```python
attachments=[AttachmentInput(kind=AttachmentKind.IMAGE, url=photo_url)]
```

Если ссылки нет (типичный случай для Telegram), скачайте файл сами и отправьте
его в том же запросе:

```python
client.submit(
    NewsSubmission(
        ...,
        attachments=[AttachmentInput(kind=AttachmentKind.IMAGE, upload_name="cover")],
    ),
    files={"cover": Path("/tmp/photo.jpg")},
)
```

## 4. Даты

`published_at` — время публикации **в источнике**, с таймзоной. Время прихода в
сервис проставляется автоматически и не подделывается парсером; по нему потом
можно отличить «новость свежая» от «парсер догнал архив».

Если время публикации неизвестно — не выдумывайте, оставьте `null`: выдача
отсортирует такую новость по времени получения.

## 5. Метки

Обычно классификацию лучше оставить классификаторам и редакторам. Но если
парсер знает что-то наверняка (канал целиком про один поток, все посты —
анонсы), есть два способа:

* `labels={"stream": ["2025"]}` в каждой новости — вес `parser`;
* **дефолты источника** в админке — вес `source_default`, выше, чем у парсера,
  и не требует изменения кода.

Оба перебиваются ручной правкой редактора.

## 6. Запуск

Свой `Dockerfile` рядом с парсером и блок в `docker-compose.yml`:

```yaml
  parser-telegram:
    build:
      context: .
      dockerfile: parsers/telegram/Dockerfile
    environment:
      NEWS_URL: http://main:8000
      NEWS_API_KEY: ${TG_PARSER_API_KEY}
    depends_on: [main]
```

Если парсер живёт в другом репозитории — ему нужен только публичный URL сервиса
и ключ; `docker-compose.yml` этого репозитория трогать не надо.

## Частые вопросы

**Что если у источника нет ссылок на посты?** Заполните `source_text`
человекочитаемым названием («Деканат ФКН, Telegram»). Хотя бы одно из
`source_link` / `source_text` / `source_key` обязательно.

**Как чинить уже отправленную новость?** Пришлите её снова с тем же
`external_id` — она будет распознана как дубликат и не изменится. Правки текста
делаются в админке; автоматическое обновление отправленных новостей сейчас не
поддерживается.

**Насколько длинным может быть текст?** Ограничений нет, `body_md` — `text`.

**Ключ утёк.** Отзовите его в админке и выпустите новый; отзыв действует сразу.
