# Авторизация v2

Все news/feed/RSS/media endpoints закрыты. API-ключ передаётся `X-API-Key`
или поддерживаемым Authorization-заголовком; ключи в URL не принимаются.
Сами ключи хранятся как хеши. Права read/ingest/editor/admin и filter preset
проверяются на сервере, включая detail по UUID, RSS и attachment ID.

Пользователь входит через `/api/v1/auth/login`. Cookie-сессии отзываемые;
HttpOnly, SameSite и Secure в production. Мутации с cookie требуют CSRF-токен.
JWT проверяется joserfc с явным Ed25519 allowlist и обязательными issuer,
audience, expiry; роль и состояние пользователя сверяются с текущей БД.

Login и выдача JWT используют общую durable rate-state по двум независимым
HMAC-идентификаторам: нормализованному account и адресу клиента. После серии
ошибок действует экспоненциальный cooldown с ограниченным максимумом; ответ
остаётся одинаковым для неизвестного, отключённого и заблокированного account.
Argon2 выполняется вне event loop, число одновременных проверок и очередь
ограничены. `X-Forwarded-For` учитывается только от IP точных proxy-hostnames,
заданных оператором; прямой клиент не может выбрать себе другой IP bucket.
Raw IP и User-Agent не сохраняются в строке browser session.

`last_used_at` API-ключа обновляется атомарной короткой транзакцией и не чаще
настраиваемого интервала. Поэтому read-only handler не откатывает отметку, а
auth-код не коммитит посторонние изменения основной request-транзакции.

Внешние классификаторы имеют отдельные Ed25519 identities. Подпись привязана
к телу, request ID, отправителю, получателю, конкретному node ID и времени.
Callback принимается только для соответствующего задания и актуальной попытки.
Повтор не перезаписывает применённый результат. Разрешённые оси проверяются
главным сервисом, а не только ограничиваются в отправленной таксономии.

Отзыв ключа/сессии и проверка пресета действуют для каждого нового запроса.
Доступные ранее ответы уже доставлены клиенту и не могут быть отозваны задним
числом. Прямые presigned GET к Garage не выдаются: media proxy проверяет
текущую связанную новость, в том числе для HEAD/Range.

После reject/delete/изменения ограничивающей разметки устаревший поисковый
индекс не используется для выдачи или агрегатов. Временный 503 означает,
что безопасная синхронизация ещё не закончена, а не разрешение читать stale data.

Первоначальные credentials создаёт init в приватных named volumes. Общих
паролей из примеров и встроенных JWT signing secrets нет. Production overlay
включает TLS через Caddy; внутренние порты не публикуются наружу.
# Защищённый AI-аудит

`GET /api/v1/admin/attempts/{attempt_id}/raw` требует scope `raw_audit`.
Перед выдачей расшифрованного ответа записывается факт доступа в аудит;
ответ имеет `Cache-Control: no-store`. Срок доступа считается от начала попытки,
по умолчанию 30 дней, независимо от её завершения. Фоновая очистка удаляет
зашифрованные payloads также у незавершённых попыток. Ошибки в обычных полях
заданий содержат коды, а не текст ответа провайдера.
