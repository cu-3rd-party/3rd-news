# 3rd-news

Собирает новости из каналов университета, раскладывает их по произвольному
набору признаков (важность, поток, тип мероприятия — что заведёшь, то и
будет) и отдаёт клиентам одной ручкой с фильтрами.

Парсеры каналов и сервисы классификации не входят в этот репозиторий. Они
общаются с главным сервисом по HTTP-контракту, поэтому их может написать
кто угодно, на чём угодно и держать у себя. Здесь лежат сам сервис, два
готовых классификатора, парсеры TiMe и RSS, и описание контрактов.

## Как устроено

Парсер шлёт новость в `POST /api/v1/ingest/news`. Главный сервис кладёт её
в базу, скачивает вложения и ставит по задаче на каждый включённый
классификатор. Воркер спрашивает классификаторы и складывает их ответы.
Итоговая разметка попадает в выдачу `GET /api/v1/news`.

Классификация разбита на независимые оси (facets). Ось — это строки в базе,
а не enum в коде: новая ось «Факультет» или значение «поток 2027» заводится
в админке за две формы, без миграции и передеплоя. Классификаторы получают
актуальную таксономию в каждом запросе, поэтому тоже ничего не требуют.

Мнения о новости хранятся отдельно и не затирают друг друга: ручная правка
редактора, дефолты источника, метки парсера и ответ каждого классификатора
лежат своими строками. Итог считается по приоритетам — ручная правка
сильнее дефолтов источника, те сильнее парсера, парсер сильнее
классификаторов, а между классификаторами решает приоритет из админки и
уверенность в ответе. Подробнее — в [docs/architecture.md](docs/architecture.md).

## Эндпоинты

Клиентские:

- `GET /api/v1/news` — выдача с фильтрами. Оси фильтруются динамически:
  `?facet.importance=critical,normal&facet.stream=2025`. Значения внутри
  одной оси — ИЛИ, разные оси — И. Плюс `q`, `source`, диапазоны дат,
  `has_attachments`, курсорная пагинация. См.
  [docs/contracts/delivery.md](docs/contracts/delivery.md).
- `GET /api/v1/news/{id}` — одна новость.
- `GET /api/v1/taxonomy` — какие оси и значения сейчас существуют.

Авторизация выдачи — API-ключ (`X-API-Key`), JWT (`Authorization: Bearer`)
или cookie-сессия. Какие способы включены, задаётся в `NEWS_AUTH_BACKENDS`;
добавление нового (в том числе SSO, когда станет понятно, какой он будет) —
это один класс и строка конфига, ручки не трогаются. См.
[docs/auth.md](docs/auth.md).

Для парсеров:

- `POST /api/v1/ingest/news` — приём одной новости, JSON или
  `multipart/form-data`, если файл надо загрузить напрямую.
- `POST /api/v1/ingest/news/batch` — до 200 штук за раз.

Для классификаторов:

- `POST /api/v1/classification/callback` — сюда медленный классификатор
  присылает результат, если ответил `202` вместо разметки.

Админские (`/api/v1/admin/...`) — оси и значения, источники, API-ключи,
реестр классификаторов, ревью новостей и ручная разметка, статистика.
Полный список с телами запросов — в Swagger на `/docs`.

## Превью ленты

`http://localhost:8000/preview` — страница, показывающая ленту глазами
клиента. Фильтры она строит из текущей таксономии, а ходит в тот же
`GET /api/v1/news`, что и любой внешний потребитель, и показывает точный URL
каждого запроса — по нему удобно писать клиент.

Смотреть лучше по ключу с правом `read`, а не под админской сессией: у
редактора видны неопубликованные новости и все статусы, у клиента — нет.
Если у ключа задан `filter_preset`, страница честно покажет суженную им
выдачу. Ключ спрашивается при первом заходе и хранится в localStorage.

## Новость

```json
{
  "external_id": "12345",
  "source_key": "tg-dekanat-fkn",
  "title": "Заголовок",
  "body_md": "Текст в **markdown**, длина не ограничивается",
  "source_link": "https://t.me/dekanat_fkn/12345",
  "source_text": "Деканат ФКН, Telegram",
  "published_at": "2026-09-01T10:30:00+03:00",
  "attachments": [{ "kind": "image", "url": "https://.../poster.jpg" }],
  "labels": { "stream": ["2025"] }
}
```

- Обязателен только `body_md` и хотя бы одно из `source_link`,
  `source_text`, `source_key`.
- `published_at` — время публикации в источнике. Время прихода в сервис
  (`received_at`) проставляется сам и парсером не подделывается: по нему
  потом видно, новость свежая или парсер догоняет архив.
- `external_id` — стабильный идентификатор поста внутри источника. Вместе с
  `source_key` он делает приём идемпотентным: повтор вернёт
  `status: "duplicate"` и ничего не изменит, поэтому парсеру не нужно
  хранить состояние и можно каждый раз перечитывать ленту с начала.
- `kind` вложения — `image`, `pdf`, `video`, `audio` или `file`. Файл по
  ссылке сервис скачает сам, асинхронно; если прямой ссылки нет, файл
  отправляется в том же multipart-запросе.
- `labels` — только то, в чём парсер уверен. Всё остальное решают
  классификаторы и редакторы.

Полный формат — [docs/contracts/ingest.md](docs/contracts/ingest.md).

## Классификаторы

В комплекте два, оба регистрируются в админке как обычные внешние сервисы:

- `classifier-regex` — ключевые слова и регулярки. Правила не в коде: он
  читает `synonyms` и `match_patterns`, заведённые на значениях осей, то
  есть настраивается через админку.
- `classifier-ai` — LLM через OpenRouter. Промпт собирается из описаний и
  подсказок (`ai_hint`) осей и значений; модель, температура и
  дополнительные инструкции приходят из настроек регистрации. Ответ модели
  фильтруется по таксономии, чтобы выдуманные метки не попали в базу.

Классификаторы получают не только новость и таксономию, но и **базу
знаний**: текст про университет, который редактор пишет один раз в админке
(расшифровки сокращений, названия потоков, кто такие кураторы), и примеры
ручной разметки. Примеры набираются сами: поправили метку на вкладке
«Новости» — решение уехало в следующие запросы как образец. Это обучение без
обучения, и чем дольше работает сервис, тем ближе разметка к принятым у вас
соглашениям.

У каждой регистрации есть приоритет, порог уверенности и флаг
`auto_apply`. С `auto_apply: false` классификатор работает «в тени»:
предложения видны редактору в админке, но на выдачу не влияют — удобный
способ выкатить новый классификатор и неделю посмотреть, что он предлагает.

Свой классификатор — это два эндпоинта, `GET /manifest` и `POST /classify`,
на любом языке и в любом репозитории. Как писать —
[docs/guides/writing-a-classifier.md](docs/guides/writing-a-classifier.md),
протокол целиком —
[docs/contracts/classifier.md](docs/contracts/classifier.md).

## Запуск через Docker (рекомендуется)

```bash
cp .env.example .env  # и поменяй NEWS_SECRET_KEY с NEWS_BOOTSTRAP_ADMIN_PASSWORD
docker compose up -d --build
```

Поднимутся Postgres, Redis, API с миграциями, воркер и оба классификатора.
При первом запуске создаётся админ из `NEWS_BOOTSTRAP_ADMIN_*` и стартовая
таксономия (важность, поток, тип, формат) — её можно править и удалять.

Дальше зарегистрировать классификаторы:

```bash
./scripts/register_classifiers.sh
```

Скрипт делает обычные вызовы админского API — те же самые, которыми
регистрируется классификатор из чужого репозитория.

API на `http://localhost:8000`, Swagger на `/docs`. Админка отдельным
профилем: `docker compose --profile ui up -d admin-ui` →
`http://localhost:5173`. Парсеры — профилем `parsers`, но сначала выпусти
каждому ключ с правом `ingest` и заполни его переменные: для TiMe это
`TIME_COOKIE` и `TIME_CHANNELS` (см. [parsers/time/README.md](parsers/time/README.md)),
для RSS — `RSS_FEEDS`.

Остановить — `docker compose down`.

## Запуск локально без Docker

Нужны Python 3.11+, поднятые Postgres и Redis.

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r services/main/requirements.txt ./packages/contracts

export NEWS_DATABASE_URL=postgresql+asyncpg://news:news@localhost:5432/news
export NEWS_REDIS_URL=redis://localhost:6379/0
export NEWS_MEDIA_ROOT=./data/media

cd services/main
alembic upgrade head
uvicorn app.main:app --reload
```

Воркер поднимается отдельным процессом, иначе новости останутся в статусе
`pending` — классификаторов никто не спросит, вложения никто не скачает:

```bash
cd services/main && python -m app.worker
```

Классификаторы — обычные приложения на uvicorn:

```bash
cd services/classifier-regex && uvicorn app.main:app --port 8101
```

Админка:

```bash
cd admin-ui && bun install && bun run dev
```

## Структура

- `services/main` — приём, хранение, таксономия, оркестрация
  классификации, выдача, админ-API, воркер.
- `services/classifier-regex`, `services/classifier-ai` — классификаторы.
- `parsers/time` — парсер каналов мессенджера ЦУ (`time.cu.ru`, это
  Mattermost). Поднимает свою страницу выбора каналов — их там больше
  полутора тысяч, см. [parsers/time/README.md](parsers/time/README.md).
  `parsers/rss` — пример на RSS/Atom; `parsers/template` — скелет для нового.
- `packages/contracts` — pydantic-модели, HMAC-подпись, клиент для
  парсеров и обёртка для классификаторов. Ставится пакетом в посторонний
  репозиторий; пользоваться им необязательно, контракт — это HTTP и JSON.
- `admin-ui` — React SPA: ревью новостей, ручная разметка, оси, ключи,
  классификаторы.
- `docs` — контракты и руководства.

Каждый сервис собирается своим `Dockerfile` с контекстом сборки в корне
репозитория (иначе в образ не попадёт `packages/contracts`), поэтому любой
из них можно вынести в отдельный репозиторий и оставить в compose только
URL.

## Деплой

`docker compose up -d --build` на VPS — самый короткий путь. Что обязательно
поменять относительно `.env.example`:

- `NEWS_SECRET_KEY` — им подписываются JWT и он же соль по умолчанию. Со
  значением из примера токены сможет выписать кто угодно.
- `NEWS_BOOTSTRAP_ADMIN_PASSWORD` — админ создаётся из него при первом
  запуске, пока таблица пользователей пуста. После создания переменную
  можно убрать.
- `NEWS_PUBLIC_BASE_URL` — публичный адрес сервиса. Из него собирается
  `callback_url`, который получают классификаторы, так что с дефолтным
  `http://main:8000` асинхронный ответ снаружи не дойдёт.
- `NEWS_ENVIRONMENT=production` — включает `secure` у сессионной куки.
- `NEWS_CORS_ORIGINS` — откуда ходит админка.

Вложения лежат на томе и раздаются самим приложением по `/media`. Для
чего-то серьёзнее пары сотен файлов в день эту раздачу стоит забрать в
nginx или CDN, а при переезде на S3 — переписать `save_bytes` и
`public_url` в `services/main/app/storage.py`, остальной код их не знает.

По умолчанию новость публикуется автоматически, как только все
классификаторы ответили и заполнены обязательные оси. Если нужно, чтобы
каждую новость глазами подтверждал редактор — `NEWS_AUTO_PUBLISH=false`.

## Тесты

Базы не требуют, гоняются из корня в том же venv:

```bash
pip install pytest
python -m pytest
```

Покрыты контракты и подпись, оба классификатора, HTTP-протокол
классификатора целиком, разбор фильтров, курсоры и дедупликация. Пути с
базой проверяются на поднятом compose.
